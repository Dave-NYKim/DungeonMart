# 모바일 터치 우선 UI 규칙 · 2026-09-11

던전 마트는 **핸드폰으로 하는 게임**이다. 모든 UI는 터치만으로 완전히 조작할 수 있어야 하고, 데스크톱(마우스·키보드·휠)은 보조 입력이다. 이 문서의 규칙은 `AGENTS.md`의 작업 규칙이며, 새 UI를 만들거나 기존 UI를 고칠 때 예외 없이 적용한다. 기준 기기는 세로 모드 스마트폰이다.

## 1. 기준 화면

- 설계 기준 뷰포트: **세로 390×844**(일반 폰). 최소 보장: **360×640**. 가로 모드와 데스크톱은 같은 UI가 넓어지는 것이지 별도 UI가 아니다.
- 데스크톱 전용 레이아웃(좌측 레일, 넓은 사이드 패널)은 폰에서 반드시 하단 메뉴·전체화면 시트로 접힌다. 폰에서 잘려 보이는 요소는 버그다.
- 페이지 가로 스크롤 금지. 고정 px 폭 대신 `%`, `vw`, `minmax()`, `flex-wrap`을 쓴다. 표·격자만 자체 `overflow-x:auto` 허용.
- `env(safe-area-inset-*)`를 하단 메뉴·상단 HUD·모달에 적용한다(노치·홈 인디케이터 회피).
- 텍스트 최소 13px. `input`·`select`는 16px 이상(iOS 자동 확대 방지).

## 2. 터치 타깃

- 탭 가능한 모든 요소는 **최소 44×44 CSS px**(권장 48). 시각적 크기가 작아도 `padding` 또는 가상 요소로 히트 영역을 44px 이상 확보한다.
- 인접한 탭 타깃 사이 간격 **8px 이상**. 삭제·분해·새 게임 같은 파괴적 버튼은 다른 버튼과 붙이지 않고 확인 단계를 둔다.
- 주요 액션(사냥터 배정, 제작, 배치, 전직, 보스 소환, 팝업 닫기)은 **화면 하단 엄지 영역**에 둔다. 닫기 버튼은 우상단 하나만 두지 말고 하단에도 "닫기/확인"을 둔다.
- 목록 항목(용사 카드, 창고 아이템, 스킬 노드)은 행 전체가 탭 타깃이다.

## 3. 호버 금지

- `:hover`는 장식(색 변화)만 허용한다. **정보나 기능이 호버에만 있으면 안 된다.** 툴팁, 미리보기, 마을 편집 고스트는 탭(또는 롱프레스)으로 열리고 다시 탭하거나 바깥을 탭하면 닫힌다.
- `title` 속성에 설명을 맡기지 않는다. 필요한 설명은 화면에 보이는 텍스트나 탭으로 여는 정보 카드로 제공한다.
- 탭 즉시 반응: `:active` 상태를 정의하고 `touch-action:manipulation`으로 300ms 지연과 더블탭 확대를 막는다. 게임 UI는 `user-select:none`, 로그·설명 텍스트만 선택 허용.

## 4. 입력 처리

- 모든 포인터 처리는 **Pointer Events**(`pointerdown/move/up/cancel` + `setPointerCapture`)로 통일한다. `mousedown`, `touchstart`, HTML5 Drag and Drop(`dragstart/drop`)은 사용 금지. HTML5 DnD는 모바일 브라우저에서 동작하지 않는다.
- 드래그 표면(맵, 사냥터 보드, 장비 격자, 마을 편집)에는 `touch-action`을 명시한다. 맵은 `none`, 세로 스크롤 목록 안의 드래그 항목은 롱프레스(약 250ms) 후 드래그 시작으로 스크롤과 구분한다.
- 드래그 중에는 손가락 아래가 가려지므로 드래그 대상 미리보기를 손가락 위쪽 오프셋(약 40px)에 그리고, 놓을 수 있는 자리를 강조한다.
- 드래그 외에 **탭 대안**을 반드시 제공한다. 사냥터 배정은 용사 탭 → 액트 탭, 장비는 아이템 탭 → 배치 버튼으로도 완료된다.
- 맵: 한 손가락 드래그 = 이동, 두 손가락 핀치 = 확대/축소, 탭 = 선택, 롱프레스 = 정보. 휠·키보드·더블클릭은 데스크톱 보조.
- `pointercancel`(브라우저 제스처 개입, 전화 수신)에서 드래그 상태를 반드시 정리한다.

## 5. 팝업과 시트

- 폰에서 모달은 **전체화면 시트**(또는 하단 시트)다. 탭 이동은 상단 세그먼트 버튼, 내부 스크롤은 시트 안에서만.
- 시트 안 긴 목록은 가상 스크롤이 아니어도 되지만 스크롤 컨테이너를 하나만 두어 중첩 스크롤을 피한다.
- 시트가 열려 있으면 뒤의 맵 제스처를 막는다(`dialog`의 `showModal` 유지).

## 6. 성능·전력

- 중급 안드로이드 폰에서 60fps, 최소 30fps. 캔버스는 `devicePixelRatio`를 반영하되 2를 상한으로 둔다.
- 탭이 숨겨지면 시뮬레이션과 렌더를 멈춘다(현재 구현 유지). 화면 밖 장식·이펙트는 그리지 않는다.
- 폰트·이미지 외부 로드 없음(현재 규칙 유지). 첫 로드 3MB 이하.

## 7. 검증 절차 (UI 변경마다)

1. Chrome DevTools 기기 모드 **390×844**와 **360×640**에서 터치 에뮬레이션을 켜고 확인한다. 마우스 호버 없이 손가락만으로 해당 기능을 끝까지 완료할 수 있어야 한다.
2. 새로 만든 탭 타깃의 크기를 DevTools로 재서 44px 미만이면 고친다.
3. `tests/browser-smoke.mjs`는 `click()` 대신 `tap()`(좌표 기반 터치)을 우선 사용하고, 새 기능의 스모크는 모바일 뷰포트로 실행한다.
4. 실제 폰에서 GitHub Pages 배포본으로 최종 확인한다(배포는 사용자가 지시할 때만).

## 8. 현재 상태 감사 (2026-09-11, 1차 터치 전환 반영)

갖춘 것:
- `<meta name="viewport" width=device-width>`, `max-width:720px` 중단점, `env(safe-area-inset)`, 하단 메뉴 `.bottom-nav`(좌측 레일은 DOM에 없음. `.rail` CSS는 잔존 규칙).
- 맵 이동·핀치는 Pointer Events + `setPointerCapture`(`src/map-input.js`), 맵에 `touch-action:none`.
- **맵 정보 탭**: 몬스터를 누르면 툴팁이 2.6초 고정 표시(`showTip` sticky). 빛기둥은 탭 즉시 획득, 시설은 탭으로 카드, 용사는 탭으로 프로필. 마우스 호버 툴팁은 그대로 보조.
- **마을 편집 터치**: 터치에서는 첫 탭이 미리보기 고스트, 같은 자리 재탭 또는 '여기에 배치' 버튼(`#town-confirm`)이 확정. 마우스는 호버 고스트 + 클릭 유지. 지우기는 탭 즉시.
- **탭 타깃**: `@media(pointer:coarse)` 블록(style.css 끝)에서 버튼 최소 44px, 하단 메뉴 56px, 시간·줌 버튼 44px(폰 40px), 맵 바로가기 2줄 접기, 아이콘 버튼 44px, 팔레트 36px, 셀렉트 44px·16px 글자, 장비 격자 셀 32px(폰 30px), 창고 행 52px, 모달 닫기 44px.
- **탭 반응**: `body{touch-action:manipulation}`(300ms 지연·더블탭 확대 제거), `button:active` 밝기 피드백.
- **`title` 의존 제거**: 스킬 강화 비용은 버튼 안 `nP` 표기, 무게 페널티 단계는 보이는 문장, 배치 불가 사유는 버튼 문구("사용 불가"/"자리 없음"), 빛기둥 배지에 "눌러서 이동", 보스 소환 설명은 확인 시트. 장비 카드의 `title` 상세는 데스크톱 보조로만 남김(탭하면 상세 패널).
- **파괴적 동작 확인**: 분해는 인라인 확인(반환 재료 표시 → '분해 확정'/'취소'), 보스 소환은 확인 시트(비용·운영금 표시), 새 게임은 기존 확인 모달.
- **드래그 대안**: 사냥터 배정은 프로필 '사냥 · 기록' 탭 버튼, 장비는 '배치' 버튼. 터치 드래그 고스트는 손가락 위(사냥터 칩 104px)로 띄움.
- **문구**: 클릭/휠/드래그 → 누르기/핀치/끌기로 통일(안내 모달, 지도 힌트, 툴팁, 전직 트리).
- 스모크 테스트: 폰 뷰포트에서 `pointer:coarse` 에뮬레이션과 탭 타깃 40px 검사 추가, 보스 소환 확인 단계 반영.
