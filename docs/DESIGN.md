# 기본 게임 설계 · 2026-09-10

현재 월드 구조와 카메라·헌터 입장 설계는 [MAP_DESIGN.md](MAP_DESIGN.md)를 기준으로 한다. 아래 내용은 전투·성장·경제의 기본 규칙이다.

## 플레이어의 역할

플레이어는 중앙 편의점의 주인이다. 용사는 직접 조작하지 않는다. 최대 20명의 용사를 영입하고, 사냥터·전직·스킬 투자·장비를 정한다. 자동 전투의 결과가 재료와 장비 세팅의 변화로 이어지는지가 첫 버전의 검증 대상이다.

## 월드

| 액트 | 마트 기준 배치 | 환경 | 해금 | 주재료 |
|---|---|---|---|---|
| I · 잿빛 황야 | 북서 | 숲, 묘지, 무너진 돌담 | 처음부터 | 철 조각 |
| II · 태양의 무덤 | 북동 | 사막, 고대 무덤, 석주 | 용사 한 명 Lv.8 | 마력석 |
| III · 몰락한 밀림 | 남서 | 열대 밀림, 늪, 폐사원 | 용사 한 명 Lv.20 | 영혼 결정 |
| IV · 불타는 지옥 | 남동 | 용암 균열, 흑요석 제단 | 용사 한 명 Lv.35 | 영혼 결정, 높은 골드·경험치 |

중앙 마트가 네 지역과 연결된다. 지역 해금은 용사 중 최고 레벨로 판단한다. 지역마다 배정할 용사는 플레이어가 결정한다. 정예는 보통 몬스터보다 높은 체력과 보상을 가진다.

## 경제

`자동 사냥 → 개인 골드 + 임시 재료 가방 → 귀환 → 공용 재료 창고 → 장비 제작 → 마트 재고 → 플레이어의 구매 선택 → 장착`

- 재료는 공용, 골드는 용사 개인 소유다.
- 제작 자체는 재료만 소비한다. 최초 구매 시 용사 골드가 마트 운영금으로 이동한다.
- 이미 구매한 장비를 다른 용사에게 옮길 때 골드를 다시 소비하지 않는다. 기존 용사에게서는 해제된다.
- 마트 운영금은 영입과 시설 개선에 사용한다.
- 분해는 원래 제작 재료의 50%를 항목별 내림하여 반환한다. 장착 중에는 분해할 수 없다.
- 무기에는 직업 제한이 있고 방어구·액세서리는 공용이다.

## 직업 트리

| 1차 | 2차 | 해당 계열의 3차 |
|---|---|---|
| 바바리안 | 광전사 | 혈투사 / 전쟁광 |
| 바바리안 | 파괴자 | 분쇄자 / 철혈 수호자 |
| 네크로맨서 | 소환술사 | 망자의 군주 / 골렘 지배자 |
| 네크로맨서 | 저주술사 | 역병술사 / 영혼 수확자 |
| 아마존 | 명사수 | 매의 눈 / 화살 폭풍 |
| 아마존 | 투창 전사 | 폭풍의 창 / 발키리 |
| 소서리스 | 원소술사 | 화염 지배자 / 빙결 지배자 |
| 소서리스 | 비전술사 | 뇌전 지배자 / 차원술사 |
| 팔라딘 | 성전사 | 심판관 / 태양 기사 |
| 팔라딘 | 수호기사 | 성역 수호자 / 빛의 사제 |

- 1차: 공통 액티브 2개.
- 2차: Lv.20, 철 35 + 마력석 12. 액티브 2개와 패시브 1개 추가.
- 3차: Lv.40, 마력석 25 + 영혼 결정 15. 액티브 1개·궁극기 1개·패시브 1개 추가.
- 이전 단계 스킬을 계승한다. 모든 액티브는 자동 사용한다.
- 레벨업마다 스킬 포인트 1개. 각 스킬 최대 Lv.5. 강화 비용은 1→2에 1P, 2→3에 2P, 3→4에 3P, 4→5에 4P다. 8개 스킬 전체 최대 강화에는 80P가 필요하지만 최대 획득량은 59P이므로 투자를 선택해야 한다. 포인트 초기화는 무료이며 실제 사용량을 전부 반환한다.
- 궁극기는 긴 재사용 대기시간을 가진 자동 스킬로 구현한다.
- 구체적인 스킬명·효과·대기시간은 중복 문서 대신 `src/data.js`를 기준으로 관리한다.

## 장비·코스튬 렌더링

전투 능력치는 `statsOf(hero, state)`, 표시 외형은 `appearanceOf(hero, state)`가 결정한다. 코스튬은 `hero.costume`에 저장하고 능력치 계산에는 사용하지 않는다.

현재 캐릭터는 24×32 픽셀 프레임과 발밑 기준점 (12, 29)을 공유한다. `src/pixel-art.js`에서 아래 레이어를 합성한다. 월드는 3600×2800 게임 좌표로 구성하고, 카메라에 보이는 영역을 절반 해상도의 별도 Canvas에 그린 후 보간 없이 확대한다. 프로필과 용사 목록도 같은 스프라이트를 사용한다.

1. 바닥 그림자와 선택 표시.
2. 망토·후면 장식.
3. 다리·몸체.
4. 갑옷·어깨·허리.
5. 머리·머리장식.
6. 무기·보조 외형.
7. 액세서리 오라·전직 표시.

장비 데이터에는 전투용 `stats`와 표시용 `appearance`를 분리해 저장한다. 방어구 등급은 갑옷과 어깨·투구 형태를 바꾸고, 무기 등급은 무기 색상·장식·발광을 바꾼다. 코스튬 팔레트를 선택하면 갑옷·의복 색상을 덮어쓴다. 장비 외형 팔레트로 돌아가면 장비 색상을 다시 사용한다.

기본 대기, 3프레임 걷기, 무기 공격 포즈와 좌우 반전을 적용했다. 다음 아트 작업에서는 같은 발 기준점과 프레임 크기를 유지하며 `cast / hurt / dead` 전용 프레임과 상하 방향을 추가한다. 그 후 `appearance`에 개별 스킨 식별자를 추가하고, 코스튬의 슬롯별 스킨이 있으면 해당 레이어만 우선 표시하도록 확장한다. 용사·몬스터·지형 스프라이트는 코드에서 생성·캐시한다. 보스는 `assets/boss.png`(PixelLab 생성, 정면 1장, 발이 하단 가장자리)를 `pixel-art.js`가 로드해 사용하며, 로드 전이나 파일이 없으면 코드로 그린 64×72 스프라이트로 대체한다. 보스 렌더 좌표(그림자·HP 바·이름 배지)는 스프라이트 크기와 `canvas.anchorY`에서 계산하므로 PNG를 다른 크기로 바꿔도 코드 수정이 필요 없다.

## 다음 검증 과제

- 장비 세팅에 따라 사냥 지속 시간·시간당 재료 수급이 얼마나 달라지는지.
- 근접 직업과 원거리 직업, 지원 직업 사이의 성장 격차.
- 액트별 속성 저항과 몬스터 패턴, 전설 장비 고유 효과.
- 스킬별 강화 분기와 전직 변경 비용.
- 픽셀 스프라이트의 방향별 동작 확대, 시전·피격·사망 애니메이션, 효과음.
- 저장 마이그레이션과 오프라인 보상.

## 입력과 화면 · 모바일 터치 우선

이 게임의 1순위 기기는 세로 모드 스마트폰이다. 모든 조작은 손가락 탭·드래그·핀치·롱프레스만으로 끝나야 하고, 마우스 호버·휠·키보드는 데스크톱 보조 입력이다. 탭 타깃 44px 이상, 호버 전용 정보 금지, 주요 액션은 하단 엄지 영역, 팝업은 전체화면 시트가 기본이다. 구체 규칙·현재 감사 목록·검증 절차는 [MOBILE_UI.md](MOBILE_UI.md)를 따른다.

## 픽셀 디자인 방향

이블헌터타이쿤의 작고 선명한 캐릭터, 탑다운 마을 배치와 읽기 쉬운 건물 실루엣을 참고한다. 마트에는 녹색 기와지붕, 크림색·주황색 차양, 진열창, 자판기와 작은 분수를 배치했다. 각 액트의 풀·모래·늪·용암은 서로 다른 제한 팔레트를 사용한다. 부드러운 그라데이션 대신 단색 픽셀 면과 명암을 사용하며, UI에는 픽셀 아이콘과 단계형 테두리를 적용한다. 한글 설명은 가독성을 위해 일반 텍스트로 표시한다.
